Ornith-1.5-122B / llmfleet item 22, Node B, review 2026-11-02

The v5 adapter preserves the OpenAI tool envelopes accepted by the pack's native
chat template. On the captured DeepSeek Harness request this changes the initial
reply from an irrelevant response about a previous assistant turn to a plan for
the requested pelican webpage. This was reproduced with ordinary decoding, using
the same checkpoint and request in both arms.

String tool arguments now preserve indentation, padding, trailing newlines,
quoted literals and literal protocol-looking text. Only the one native XML
framing newline on either side is removed. Both the streaming and non-streaming
paths round-trip both supplied HTML fixtures exactly. Invalid histories return a
clear error instead of silently dropping the tools and history.

Reasoning that exhausts its output budget stays in reasoning_content rather than
being copied into the answer. Both response modes preserve the full reasoning
tail, and implicit thinking-to-tool transitions keep the preceding thought separate.

The adapter reads temperature 0.6, top_k 20 and top_p 0.95 from the bundled model
config. Explicit temperature 0 remains greedy. top_k, min_p, supported penalties
and seed are honored. REASONING and RBUDGET control startup defaults; per-request
values override them. The fleet boot action is one restart command so PROFILE,
CTX, REASONING and RBUDGET reach startup. The configured request ceiling remains
131072 tokens, with the context-room check applied before streaming headers.

AR is the selected quality default, matching the ordinary-decoder reference.
The speculative controls changed token choices in the numerical comparison, so
the faster MTP2 profile remains explicit (PROFILE=MTP2 / SPEC=mtp2). Sampled
2k/256-token FP32-state code probes measured medians of 23.06 tok/s for AR,
31.17 for MTP2 and 32.96 for DFlash2 with NDT=2 (two repeats per mode).
DFlash2 remains opt-in with its original depth 15. NDT=2 now actually caps its
verification window, via EXL3_DRAFT_TOKENS, and /props reports the effective depth.
Matched greedy 2k/192-token probes measured 24.0 tok/s at depth 15 and 30.6 at
2. This is an optional speed setting, not a claim of exact AR equivalence.

The launcher uses the full-precision router projection in every mode on this
single-GPU server (EXL3_ROUTER_DET=0), matching the reference/tuning configuration.
It stores GDN recurrent state in FP32, retaining precision between passes; the
former FP16 state remains available with RECURRENT_STATE_DTYPE=fp16. This does
not eliminate all speculative differences. It defaults to one CPU math thread
and one active model-cache slot.
The server already serializes generation. Prefill chunks remain 2048. A 4096
chunk measured faster but changed token preferences in the long-context control,
so it is only an explicit PREFILL_CHUNK option. No weight or native-kernel
precision reduction, power-profile change, or node-A change was made.
